# CW Runner 设计文档

## 1. 项目概述

### 1.1 产品定位
CW Runner 是一款面向业余无线电爱好者及 CW 学习者的微信小程序，提供等幅电报（Continuous Wave）的模拟发报与异步听抄练习功能。

### 1.2 核心设计原则
- **匿名性**：模拟报文列表不展示发送者身份，规避 UGC 内容审核风险
- **异步性**：非实时通信，用户随时上传、随时播放
- **拟真性**：虚拟自动键手感贴近真实 Paddle，音频合成还原 CW 听觉体验
- **可调速**：WPM（Words Per Minute）5-40 可调，发报与播放均按实际 WPM 计算时长
- **侧音可开关**：默认静音，用户可手动开启侧音或仅使用视觉/振动反馈

## 3. 模块设计

### 3.1 输入模块（Paddle）

#### 3.1.1 界面布局
- **顶部操作栏**：帮助按钮、保存按钮、删除按钮
- **时序显示区**：实时显示当前输入的原始时序文本（如 `.-...-..|--.-`），可滚动
- **电键速度滑块**：WPM 调节（5-40 WPM）
- **报文间隔滑块**：单词间隔调节（2-6 unit，默认 2）
- **视觉反馈区**：左桨点（·）和右桨划（−）的闪烁指示
- **开关区**：侧音开关、振动开关
- **下半区**：左右双按钮（左 dit / 右 dah）

#### 3.1.2 交互逻辑

| 操作 | 行为 | 时序记录 |
|------|------|----------|
| 点下左桨 | 发点，若按住则自动连续发点 | 追加 `.` |
| 点下右桨 | 发划，若按住则自动连续发划 | 追加 `-` |
| 左右同时按 | 优先后发（Iambic B 模式） | 按实际输出记录 |
| 松手后 > wordGapUnits × unit | 单词间隔 | 追加 `\|` |
| 点击删除按钮 | 删除时序文本最后一个字符 | 删除末尾字符 |
| 点击保存按钮 | 上传当前时序文本到云端 | 清空时序区 |

注：`/` 不再由电键生成，仅在播放旧数据时兼容解析。

#### 3.1.3 自动键时序参数（以 WPM 为基准）

```
unit = 1200 / WPM ms
点长 (dit)    = 1 × unit          （20 WPM 时 60ms）
划长 (dah)    = 3 × unit          （20 WPM 时 180ms）
点划间隔      = 1 × unit          （20 WPM 时 60ms）
单词间隔      = wordGapUnits × unit  （2-6 可调，默认 2，即 20 WPM 时 120ms）
默认 WPM      = 15
```

#### 3.1.4 Iambic 模式
当左右两桨同时按下时，采用 Iambic B 模式：
1. 若当前正在发点，则下一周期发划
2. 若当前正在发划，则下一周期发点
3. 两桨均松开时，完成当前周期后停止

#### 3.1.5 删除功能
- 点击「删除」按钮，删除 `timingText` 最后一个字符
- 同步更新 `PaddleKeyer.timingText`
- 取消当前间隔定时器，避免删除后继续追加 `|`

#### 3.1.6 侧音、振动与视觉反馈
- **侧音开关**：控制按键时是否播放 600Hz 正弦波侧音。默认关闭，用户首次触摸 Paddle 区域后激活 WebAudio 上下文
- **振动开关**：控制每次发点/划时是否触发短振动（`wx.vibrateShort()`）。默认关闭，需手机系统设置中开启"触摸时振动"
- **视觉反馈**：Paddle 按钮上方有 `·` 和 `−` 两个指示灯，发点时 `·` 闪烁，发划时 `−` 闪烁

### 3.2 音频模块（WebAudio API）

#### 3.2.1 架构
使用微信小程序 `wx.createWebAudioContext()` 创建 WebAudio 上下文，通过振荡器（OscillatorNode）+ 增益节点（GainNode）实时合成 600Hz 正弦波。

- **优势**：延迟 < 1ms，无需预生成音频文件，WPM 变化时无需替换音频资源
- **生命周期**：振荡器在 `initAudio()` 时创建并持续运行（`oscillator.start(0)`），通过 `gainNode.gain.value` 控制发声/静音
- **音频激活**：首次需由用户手势触发 `activateAudio()`（调用 `audioCtx.resume()`），之后上下文保持 running 状态

#### 3.2.2 音频播放器
- 全局单例：一个 `OscillatorNode` + 一个 `GainNode`
- `playTone(type)`: 设置 gain=1 发声
- `stopTone()`: 设置 gain=0 静音
- 无需播放器池，无需轮询

#### 3.2.3 播放解析规则（playCode）

遍历 `code` 字符串，使用 `gainNode.gain.setValueAtTime()` 精确调度，由音频硬件时钟驱动：

| 字符 | 行为 |
|------|------|
| `.` | gain=1 持续 unitSec，gain=0 持续 unitSec |
| `-` | gain=1 持续 3×unitSec，gain=0 持续 unitSec |
| `\|` | 静音 wordGapUnits×unitSec |
| `/` | 静音 2×unitSec（仅兼容旧数据，新报文不包含此字符） |

静音模式下（侧音关闭），跳过 WebAudio 调度，仅用 `setTimeout` 等待对应时长后 resolve。

#### 3.2.4 音频文件（保留）
`miniprogram/assets/audio/` 目录下保留 `dit.wav` 和 `dah.wav`，为历史遗留文件，当前实现不再使用。

### 3.3 存储模块（云端 / 本地 Mock）

#### 3.3.0 存储模式切换

通过 `miniprogram/utils/config.js` 中的 `CLOUD_ENABLED` 常量控制：

| 模式 | CLOUD_ENABLED | 存储位置 | 适用场景 |
|------|---------------|----------|----------|
| 云端模式 | `true` | 微信云数据库 | 正式使用，多用户共享报文 |
| 本地模式 | `false` | 内存 Mock 数组 | 开发调试，无云环境权限时使用 |

#### 3.3.1 数据模型

```json
{
  "_id": "云数据库自动生成的ID",
  "code": "-.-.|--.-",
  "wpm": 15,
  "timestamp": 1713862800,
  "sender": "openid_xxx"
}
```

#### 3.3.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | String | 原始时序文本，仅包含 `.` `-` `\|`（`/` 仅兼容旧数据） |
| `wpm` | Number | 发报速度（Words Per Minute），播放端据此计算时长 |
| `timestamp` | Number | 创建时间 Unix 时间戳 |
| `sender` | String | 发送者匿名标识（openid 前 16 位，不返回客户端） |

#### 3.3.3 自动过期策略

报文存储 5 分钟后自动删除：
- 实现方式：被动清理（每次 `getCWList` 查询时，先删除 `timestamp < now - 300s` 的记录）
- 原因：微信云开发无内置 Cron 定时任务
- 效果：列表中永远只显示最近 5 分钟的报文

#### 3.3.4 接口（云端模式）

> 本地模式时，uploadCW / getCWList 直接操作内存 Mock 数组，不走云函数。

**uploadCW**
- 参数：`{ code: string, wpm: number }`
- 校验：
  - code 不能为空，长度 <= 500
  - code 仅允许字符 `.` `-` `/` `\|`
  - wpm 必须在 5-60 之间
  - 频率限制：单用户每小时最多 50 条
- 逻辑：获取 openid → 生成匿名 sender → 写入云数据库
- 返回：`{ success: true, id: string }`

**getCWList**
- 参数：`{ limit?: number, offset?: number }`
- 校验：limit 1-50，offset >= 0
- 逻辑：先清理过期数据，再按 `timestamp` 倒序查询，分页返回，不返回 `sender` 字段
- 返回：`{ success: true, list: Array }`

**getOpenid**
- 无参数
- 返回：`{ openid: string }`
- 仅云端模式使用

#### 3.3.5 匿名策略
- 服务端存储 `sender` 字段用于去重或反垃圾，但绝不返回给客户端
- 客户端列表仅展示 `code`、`wpm`、`timestamp`
- 用户无法知道某条 CW 是谁发的

### 4.3 交互流程

```

       |
       v

       |
       v
播放侧音（如已开启）+ 振动（如已开启）+ 视觉闪烁
       |
       v
记录时序文本 (. / -)
       |
       v

       |
       v
调节 WPM / 报文间隔（可选）
       |
       v

       |
       v
调用 uploadCW → 写入云数据库（或本地 Mock）
       |
       v

```

#### 4.3.2 收报/听抄流程

```
用户浏览模拟报文列表（滚动触底自动加载更多）
       |
       v

       |
       v
WebAudio gainNode.setValueAtTime 按 code + wpm 精确调度播放
       |
       v
用户听抄，对照时序文本
```

## 6. 技术选型

### 6.1 前端
- 微信小程序原生框架
- WebAudio API（`wx.createWebAudioContext()`）：OscillatorNode + GainNode 实时合成 600Hz 正弦波
- 振荡器持续运行，通过增益节点控制发声/静音，延迟 < 1ms

### 6.2 后端
- 微信云开发（CloudBase）
- 云数据库：MongoDB 风格文档数据库
- 云函数：Node.js 运行时

### 6.3 开发环境
- VS Code + 小程序扩展（WXML 语言服务、wxml 格式化）
- 微信开发者工具 Linux 社区版（Wine 运行）

## 7. 安全与合规

### 7.1 UGC 风险规避
- 模拟报文列表仅展示 CW 时序文本（`.` `-` `\|`），不包含任何自然语言
- 不展示发送者身份，无法建立社交关系
- 无评论、点赞、私信等社交功能

### 7.2 内容过滤
- 云函数端校验 code 字段，仅允许合法字符（`.` `-` `/` `\|`，`/` 为兼容旧数据保留）
- 客户端同样做前置校验
- 长度限制：最大 500 字符
- 频率限制：单用户每小时最多 50 条
