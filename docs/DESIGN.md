# CW Runner 设计文档

## 1. 项目概述

### 1.1 产品定位
CW Runner 是一款面向业余无线电爱好者及 CW 学习者的微信小程序，提供等幅电报（Continuous Wave）的模拟发报与异步听抄练习功能。

### 1.2 核心设计原则
- **匿名性**：模拟报文列表不展示发送者身份，规避 UGC 内容审核风险
- **异步性**：非实时通信，用户随时上传、随时播放
- **拟真性**：虚拟自动键手感贴近真实 Paddle，音频合成还原 CW 听觉体验
- **可调速**：WPM（Words Per Minute）5-40 可调，发报与播放均按实际 WPM 计算时长

## 3. 模块设计

### 3.1 输入模块（Paddle）

#### 3.1.1 界面布局
- **屏幕上半区**：实时显示当前输入的原始时序文本（如 `.-/-.../.-.`）
- **时序区底部**：WPM 调节滑块（5-40 WPM）
- **屏幕下半区**：左右双按钮（左 dit / 右 dah）

#### 3.1.2 交互逻辑

| 操作 | 行为 | 时序记录 |
|------|------|----------|
| 点下左桨 | 发点，若按住则自动连续发点 | 追加 `.` |
| 点下右桨 | 发划，若按住则自动连续发划 | 追加 `-` |
| 左右同时按 | 优先后发（iambic 模式） | 按实际输出记录 |
| 松手后 > 3 点长 | 字母间隔 | 追加 `/` |
| 松手后 > 7 点长 | 单词间隔 | 追加 `\|` |

#### 3.1.3 自动键时序参数（20 WPM 基准）

```
点长 (unit) = 1200 / WPM ms
            = 60ms  @ 20 WPM
划长 (dash) = 3 * unit
点划间隔 (intra-char gap) = 1 * unit
字母间隔 (inter-char gap) = 3 * unit
单词间隔 (inter-word gap) = 7 * unit
```

> WPM 与 unitMs 关系：标准 PARIS 参考词。WPM 越大，unitMs 越小，发报越快。
> - 5 WPM  → unitMs = 240ms
> - 20 WPM → unitMs = 60ms（设计基准）
> - 40 WPM → unitMs = 30ms

#### 3.1.4 Iambic 模式
当左右两桨同时按下时，采用 Iambic B 模式：
1. 若当前正在发点，则下一周期发划
2. 若当前正在发划，则下一周期发点
3. 两桨均松开时，完成当前周期后停止

#### 3.1.5 状态机

```
[空闲] --按下左桨--> [发点中]
[空闲] --按下右桨--> [发划中]
[发点中] --松开左桨--> [等待间隔]
[发划中] --松开右桨--> [等待间隔]
[等待间隔] --超时3点长--> [追加/] --> [空闲]
[等待间隔] --超时7点长--> [追加|] --> [空闲]
[等待间隔] --按下任一键--> [发点中/发划中]
```

### 3.2 音频模块（Web Audio）

#### 3.2.1 架构
使用微信小程序内置的 Web Audio API 进行本地音频合成。

#### 3.2.2 延迟优化策略

| 优化点 | 原始方案 | 优化后方案 | 效果 |
|--------|----------|-----------|------|
| 音频生成 | 每次按键实时创建 Oscillator + GainNode | 预生成 `AudioBuffer`（`OfflineAudioContext` 渲染） | 消除实时合成开销 |
| 按键到发声 | 通过 JS 逻辑层调度 | `touchstart` → 直接 `playBuffer()` | 延迟降至 5ms 内 |
| 连续点划 | 嵌套 `setTimeout` 累积误差 | `AudioContext.currentTime` 时间轴精确调度 | 消除累积误差 |

**为什么不采用 Base64 预生成音频？**

微信小程序不支持直接播放 Base64 音频 Buffer。`wx.createInnerAudioContext()` 需要物理文件路径，Base64 解码后仍需写入临时文件，反而增加 I/O 延迟。`AudioBuffer` 是内存中的原始 PCM 数据，通过 `createBufferSource()` 直接播放，延迟最低。

#### 3.2.3 音频图（播放预生成 Buffer）

```
+---------------+    +----------+
| BufferSource  |--->|AudioDestination|
| (预生成 dit/dah) |    |  (扬声器)      |
+---------------+    +----------+
```

#### 3.2.4 包络设计

预生成阶段在 `OfflineAudioContext` 中计算好包络：
- Attack: 5ms（线性淡入）
- Release: 5ms（线性淡出）
- Sustain: 峰值音量 0.3

#### 3.2.5 播放解析规则（按实际 WPM）

遍历 `code` 字符串，按以下规则生成音频事件。所有时长按 `speedRatio = 20 / wpm` 比例缩放：

| 字符 | 行为 |
|------|------|
| `.` | 播放 unitMs 音 + unitMs 静音 |
| `-` | 播放 3*unitMs 音 + unitMs 静音 |
| `/` | 追加 2*unitMs 静音（总间隔 3*unitMs） |
| `\|` | 追加 6*unitMs 静音（总间隔 7*unitMs） |

### 3.3 存储模块（云端 / 本地 Mock）

#### 3.3.0 存储模式切换

通过 `miniprogram/utils/config.js` 中的 `CLOUD_ENABLED` 常量控制：

| 模式 | CLOUD_ENABLED | 存储位置 | 适用场景 |
|------|---------------|----------|----------|
| 云端模式 | `true` | 微信云数据库 | 正式使用，多用户共享报文 |
| 本地模式 | `false` | 内存 Mock 数组 | 开发调试，无云环境权限时使用 |

**本地模式特点：**
- 报文保存在内存中的 `MOCK_LIST` 数组，页面刷新后丢失
- 内置 3 条示例数据，新保存的报文追加到数组头部（最多保留 20 条）
- 不依赖云开发环境，无需配置 AppID 和云环境 ID

#### 3.3.1 数据模型

```json
{
  "_id": "云数据库自动生成的ID",
  "code": "-.-./--.-",
  "wpm": 20,
  "timestamp": 1713862800,
  "sender": "openid_xxx"
}
```

#### 3.3.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | String | 原始时序文本，仅包含 `.` `-` `/` `\|` |
| `wpm` | Number | 发报速度（Words Per Minute），播放端据此计算时长 |
| `timestamp` | Number | 创建时间 Unix 时间戳 |
| `sender` | String | 发送者匿名标识（openid 前 16 位） |

#### 3.3.3 自动过期策略

报文存储 5 分钟后自动删除：
- 实现方式：被动清理（每次 `getCWList` 查询时，先删除 `timestamp < now - 300s` 的记录）
- 原因：微信云开发无内置 Cron 定时任务
- 效果：列表中永远只显示最近 5 分钟的报文

#### 3.3.4 接口（云端模式）

> 本地模式时，uploadCW / getCWList 直接操作内存 Mock 数组，不走云函数。

**uploadCW**
- 参数：`{ code: string, wpm: number }`
- 校验：
  - code 不能为空，长度 <= 500
  - code 仅允许字符 `.` `-` `/` `\|`
  - wpm 必须在 5-60 之间
  - 频率限制：单用户每小时最多 50 条
- 逻辑：获取 openid → 生成匿名 sender → 写入云数据库
- 返回：`{ success: true, id: string }`

**getCWList**
- 参数：`{ limit?: number, offset?: number }`
- 校验：limit 1-50，offset >= 0
- 逻辑：按 `timestamp` 倒序查询，分页返回
- 返回：`{ success: true, list: Array }`（不含 sender 字段）

**getOpenid**
- 无参数
- 返回：`{ openid: string }`
- 仅云端模式使用

#### 3.3.5 匿名策略
- 服务端存储 `sender` 字段用于去重或反垃圾，但绝不返回给客户端
- 客户端列表仅展示 `code`、`wpm`、`timestamp`
- 用户无法知道某条 CW 是谁发的

### 4.2 交互流程

#### 4.2.1 发报流程

```
用户按下左/右桨
       |
       v
本地 Web Audio 实时播放 600Hz 音（按当前 WPM 速度）
       |
       v
记录时序文本 (. / -)
       |
       v
松手后根据间隔自动追加 / 或 |
       |
       v
调节 WPM（可选，默认 20）
       |
       v
点击 [保存] 按钮
       |
       v
调用 uploadCW → 写入云数据库（或本地 Mock）
       |
       v
列表自动刷新
```

#### 4.2.2 收报/听抄流程

```
用户浏览模拟报文列表
       |
       v
点击某条记录的 [播放] 按钮
       |
       v
本地 Web Audio 按 code + wpm 解析播放
       |
       v
用户听抄，对照时序文本
```

## 7. 安全与合规

### 7.1 UGC 风险规避
- 模拟报文列表仅展示 CW 时序文本（`.` `-` `/` `\|`），不包含任何自然语言
- 不展示发送者身份，无法建立社交关系
- 无评论、点赞、私信等社交功能

### 7.2 内容过滤
- 云函数端校验 code 字段，仅允许合法字符
- 长度限制：最大 500 字符
- 频率限制：单用户每小时最多 50 条
