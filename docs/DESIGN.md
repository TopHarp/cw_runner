# CW Runner 设计文档

## 1. 项目概述

### 1.1 产品定位
CW Runner 是一款面向业余无线电爱好者及 CW 学习者的微信小程序，提供等幅电报（Continuous Wave）的模拟发报与异步听抄练习功能。

### 1.2 核心设计原则
- **匿名性**：模拟报文列表不展示发送者身份，规避 UGC 内容审核风险
- **异步性**：非实时通信，用户随时上传、随时播放
- **拟真性**：虚拟自动键手感贴近真实 Paddle，音频合成还原 CW 听觉体验
- **可调速**：WPM（Words Per Minute）5-40 可调，发报与播放均按实际 WPM 计算时长

## 3. 模块设计

### 3.1 输入模块（Paddle）

#### 3.1.1 界面布局
- **屏幕上半区**：实时显示当前输入的原始时序文本（如 `.-/-.../.-.`）
- **时序区操作栏**：保存按钮、删除按钮（逐字符删除）
- **时序区底部**：WPM 调节滑块（5-40 WPM）
- **屏幕下半区**：左右双按钮（左 dit / 右 dah）

#### 3.1.2 交互逻辑

| 操作 | 行为 | 时序记录 |
|------|------|----------|
| 点下左桨 | 发点，若按住则自动连续发点 | 追加 `.` |
| 点下右桨 | 发划，若按住则自动连续发划 | 追加 `-` |
| 左右同时按 | 优先后发（iambic 模式） | 按实际输出记录 |
| 松手后 > 7 点长 | 单词间隔 | 追加 `\|` |
| 点击删除按钮 | 删除时序文本最后一个字符 | 删除末尾字符 |

#### 3.1.3 自动键时序参数（20 WPM 基准）

```
点长 (unit) = 1200 / WPM ms
            = 60ms  @ 20 WPM
划长 (dash) = 3 * unit
点划间隔 (intra-char gap) = 1 * unit
单词间隔 (inter-word gap) = 7 * unit
```

#### 3.1.4 Iambic 模式
当左右两桨同时按下时，采用 Iambic B 模式：
1. 若当前正在发点，则下一周期发划
2. 若当前正在发划，则下一周期发点
3. 两桨均松开时，完成当前周期后停止

#### 3.1.5 删除功能
- 点击「删除」按钮，删除 `timingText` 最后一个字符
- 同步更新 `PaddleKeyer.timingText`
- 取消当前间隔定时器，避免删除后继续追加 `|`

### 3.2 音频模块（InnerAudioContext）

#### 3.2.1 架构
使用微信小程序 `wx.createInnerAudioContext({ useWebAudioImplement: true })` 播放预生成的本地 WAV 音频文件。

#### 3.2.2 音频文件
- `miniprogram/assets/audio/dit.wav` — 点音（60ms @ 20WPM）
- `miniprogram/assets/audio/dah.wav` — 划音（180ms @ 20WPM）

#### 3.2.3 播放器池
创建 4 个 `InnerAudioContext` 实例轮询使用，避免频繁创建销毁。

#### 3.2.4 播放解析规则（按实际 WPM）

遍历 `code` 字符串，按以下规则调度播放：

| 字符 | 行为 |
|------|------|
| `.` | 播放 dit 音，等待 2*unitMs |
| `-` | 播放 dah 音，等待 4*unitMs |
| `/` | 追加 2*unitMs 静音 |
| `\|` | 追加 6*unitMs 静音 |

### 3.3 存储模块（云端 / 本地 Mock）

#### 3.3.0 存储模式切换

通过 `miniprogram/utils/config.js` 中的 `CLOUD_ENABLED` 常量控制：

| 模式 | CLOUD_ENABLED | 存储位置 | 适用场景 |
|------|---------------|----------|----------|
| 云端模式 | `true` | 微信云数据库 | 正式使用，多用户共享报文 |
| 本地模式 | `false` | 内存 Mock 数组 | 开发调试，无云环境权限时使用 |

#### 3.3.1 数据模型

```json
{
  "_id": "云数据库自动生成的ID",
  "code": "-.-./--.-",
  "wpm": 20,
  "timestamp": 1713862800,
  "sender": "openid_xxx"
}
```

#### 3.3.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | String | 原始时序文本，仅包含 `.` `-` `/` `\|` |
| `wpm` | Number | 发报速度（Words Per Minute），播放端据此计算时长 |
| `timestamp` | Number | 创建时间 Unix 时间戳 |
| `sender` | String | 发送者匿名标识（openid 前 16 位） |

#### 3.3.3 自动过期策略

报文存储 5 分钟后自动删除：
- 实现方式：被动清理（每次 `getCWList` 查询时，先删除 `timestamp < now - 300s` 的记录）
- 原因：微信云开发无内置 Cron 定时任务
- 效果：列表中永远只显示最近 5 分钟的报文

#### 3.3.4 接口（云端模式）

> 本地模式时，uploadCW / getCWList 直接操作内存 Mock 数组，不走云函数。

**uploadCW**
- 参数：`{ code: string, wpm: number }`
- 校验：
  - code 不能为空，长度 <= 500
  - code 仅允许字符 `.` `-` `/` `\|`
  - wpm 必须在 5-60 之间
  - 频率限制：单用户每小时最多 50 条
- 逻辑：获取 openid → 生成匿名 sender → 写入云数据库
- 返回：`{ success: true, id: string }`

**getCWList**
- 参数：`{ limit?: number, offset?: number }`
- 校验：limit 1-50，offset >= 0
- 逻辑：按 `timestamp` 倒序查询，分页返回
- 返回：`{ success: true, list: Array }`（不含 sender 字段）

**getOpenid**
- 无参数
- 返回：`{ openid: string }`
- 仅云端模式使用

#### 3.3.5 匿名策略
- 服务端存储 `sender` 字段用于去重或反垃圾，但绝不返回给客户端
- 客户端列表仅展示 `code`、`wpm`、`timestamp`
- 用户无法知道某条 CW 是谁发的

### 4.2 交互流程

#### 4.2.1 发报流程

```
用户按下左/右桨
       |
       v
本地 InnerAudioContext 播放预生成 WAV 音
       |
       v
记录时序文本 (. / -)
       |
       v
松手后根据间隔自动追加 / 或 |
       |
       v
调节 WPM（可选，默认 20）
       |
       v
点击 [保存] 按钮
       |
       v
调用 uploadCW → 写入云数据库（或本地 Mock）
       |
       v
列表自动刷新
```

#### 4.2.2 收报/听抄流程

```
用户浏览模拟报文列表
       |
       v
点击某条记录的 [▶] 按钮
       |
       v
本地 InnerAudioContext 按 code + wpm 解析播放
       |
       v
用户听抄，对照时序文本
```

## 7. 安全与合规

### 7.1 UGC 风险规避
- 模拟报文列表仅展示 CW 时序文本（`.` `-` `/` `\|`），不包含任何自然语言
- 不展示发送者身份，无法建立社交关系
- 无评论、点赞、私信等社交功能

### 7.2 内容过滤
- 云函数端校验 code 字段，仅允许合法字符
- 长度限制：最大 500 字符
- 频率限制：单用户每小时最多 50 条
